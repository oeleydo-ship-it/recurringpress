Invoice Manager

A multi-tenant invoicing SaaS. Businesses sign up and create quotations and invoices, then get paid online by card. You, the platform owner, sell subscription plans and manage everything from a Superadmin panel.

Laravel 13PHP 8.3+React 19 + InertiaMySQL / MariaDBStripeRedis & Horizon (optional)

This guide has two parts. Installation is for whoever sets up the server. The Superadmin and Tenant chapters explain how to use the platform day to day.

Overview #

The platform has three kinds of users:

WhoWhere they sign inWhat they do
Superadmin (you, the platform owner)/superadmin/loginConfigures Stripe and email, creates subscription plans, manages tenants, approves payouts, and edits the public website, pages, blog and menus.
Tenant users (a business: Owner, Admin, Member)/login (sign up at /register)Manage clients, products, quotations, invoices, recurring invoices, expenses, payments and receipts for their own company. Each company's data is isolated from every other company.
Clients (customers of a tenant)No account needed: they use a private linkView, download and pay invoices, and accept or reject quotations.

Feature list

  • Quotations that clients accept or reject online, then convert to an invoice with one click. A client can also pay a quotation directly.
  • Invoices with line items, tax and discount. There are 12 PDF templates, plus email sending, duplication, CSV export, manual payments and refunds.
  • Recurring invoices, generated automatically on a schedule (pause, resume, cancel, or generate now).
  • Online card payments through Stripe, using either the platform's account or the tenant's own account.
  • Payments, receipts and payouts (payouts are for tenants paid through the platform Stripe account).
  • Expenses with receipt uploads, plus reports and a dashboard.
  • Team members with roles; subscription plans with usage limits.
  • Marketing website: landing page, pricing, features, FAQ, contact, a blog and CMS pages with a block builder.
  • Security: email verification, rate limiting, spam honeypots, security headers and per-company data isolation.

What to upload #

Upload the complete release package. On shared hosting you usually can't run Composer or npm, so the package must already contain:

  • vendor/: the PHP dependencies (from composer install --no-dev --optimize-autoloader).
  • public/build/: the compiled React front-end (from npm ci && npm run build). Without it every page is blank.
  • bootstrap/ssr/: the SSR bundle (only used if you run SSR).
  • install.json in the project root. Its presence enables the web installer.
  • .env.example. The installer copies it to .env.

The package must not contain a .env file, storage/installed, node_modules/, logs, or anything in storage/app/public from your test machine.

Building the release package yourself (developers) 
composer install --no-dev --optimize-autoloader
npm ci
npm run build                      # builds public/build and bootstrap/ssr
cp install.json.installed install.json   # if your copy only has the .installed version
# then zip everything except: .env, node_modules, .git, storage/installed,
# storage/logs/*, storage/framework/{cache,sessions,views}/*

Installing on cPanel #

This walkthrough uses an example cPanel username myuser and domain billing.example.com. Replace both with your own.

1. Select PHP 8.3 or 8.4 #

  1. In cPanel open Software → MultiPHP Manager. Tick your domain and set PHP Version to ea-php83 or ea-php84, then click Apply.
    On CloudLinux servers this is Select PHP Version instead. Choose 8.3/8.4 and enable the extensions listed above.
  2. Open MultiPHP INI Editor, pick the domain, and set memory_limit = 256M, upload_max_filesize = 10M, post_max_size = 12M and max_execution_time = 120.

2. Create the database #

  1. Open Databases → MySQL® Database Wizard.
  2. Create a database, e.g. myuser_invoice.
  3. Create a user, e.g. myuser_invoice, with a strong password (use the generator).
  4. On the privileges screen tick ALL PRIVILEGES and finish.
  5. Write down the database name, username and password. Note that cPanel adds your account prefix (myuser_) to both names.

3. Upload and extract the files #

  1. Open Files → File Manager and go to your home folder /home/myuser. Use your home folder, not public_html.
  2. Create a folder, e.g. invoiceapp, and upload the release .zip into it.
  3. Right-click the zip → Extract. You should end up with /home/myuser/invoiceapp/app, /home/myuser/invoiceapp/public, /home/myuser/invoiceapp/artisan and so on (not an extra nested folder).
  4. Select storage and bootstrap/cache → Permissions → 775, with "Recurse into subdirectories" ticked.
💡 Tip

Keeping the app outside public_html means .env, vendor/ and storage/ can never be downloaded from the web. Only the public/ folder is exposed.

4. Point the domain at the public folder #

Recommended: use a subdomain or addon domain.

  1. Open Domains → Domains (older cPanel: Subdomains or Addon Domains).
  2. Click Create A New Domain (or Manage on an existing one) and set the Document Root to invoiceapp/public.
  3. Save. Visiting https://billing.example.com should now load the app.
Main domain whose document root is locked to public_html

Some hosts don't allow changing the primary domain's root. Use one of these options:

Option A (symlink, preferred). Using cPanel Terminal or SSH:

cd ~
mv public_html public_html.bak
ln -s ~/invoiceapp/public ~/public_html

Option B (.htaccess forwarder). Upload the whole app into public_html and create public_html/.htaccess with:

<IfModule mod_rewrite.c>
    RewriteEngine On
    # Never serve hidden files (.env, .git) or app folders directly
    RewriteRule ^(\.|app/|bootstrap/|config/|database/|resources/|routes/|storage/|vendor/|artisan|composer\.) - [F,L,NC]
    RewriteRule ^(.*)$ public/$1 [L]
</IfModule>
⚠️ Warning

Option B is a fallback. After installing, open https://your-domain/.env in a browser and confirm you get 403 Forbidden. If the file downloads, remove the files immediately and use Option A instead.

5. Run the web installer #

Open your domain in a browser. Until installation finishes, every page redirects to /install.

  1. Welcome: shows the app name and version. Click Start.
  2. Requirements: PHP version, extensions and folder permissions must all show green. If something is red, fix it (step 1 or the permissions in step 3) and reload.
  3. Database: host localhost, port 3306, and the database name, user and password from step 2. Click Test connection and then continue.
  4. Application: the site name and the exact URL including https:// (e.g. https://billing.example.com). Email verification links are signed against this URL.
  5. Admin account: two logins.
    • Your name, company name, email and password. This becomes the Owner of the first tenant company (on the top plan), so you can try the business side straight away.
    • Platform Superadmin login: a separate email and password for /superadmin/login. The password needs at least 8 characters with upper and lowercase letters and a number. Don't reuse the Owner password.
  6. Install: the installer writes .env, generates the app key, runs migrations, creates the Superadmin with the login from the previous step, runs the seeders (plans, system settings, CMS pages), links storage and clears caches.
  7. Complete: an installed marker is written to storage/installed. The installer is now permanently disabled.
🛑 Installs from the command line get a default Superadmin login

The web installer uses the Superadmin email and password you enter, so it creates no default login. If you install without it (php artisan migrate --seed or php artisan db:seed on an empty database), the seeder creates a Superadmin with email admin@invoiceapp.com and password password and prints a warning. Change both right away, as described in First login. Until you do, anyone who knows the default can take over the platform. Running the seeder again later never resets or adds a Superadmin once one exists.

6. Add the cron job #

Open Advanced → Cron Jobs, choose Once Per Minute (* * * * *) and enter:

/usr/local/bin/php /home/myuser/invoiceapp/artisan schedule:run >> /dev/null 2>&1

If your account has several PHP versions, use the 8.3/8.4 binary explicitly, e.g. /opt/cpanel/ea-php84/root/usr/bin/php. Ask your host if you're unsure which path to use.

The scheduler runs these tasks:

TaskFrequency
Generate due recurring invoicesDaily
Mark unpaid invoices as overdueDaily
Expire old quotationsDaily
Check for platform updatesDaily
Horizon metrics snapshot (only if Horizon is used)Every 5 minutes

7. SSL, email and hardening #

  1. Security → SSL/TLS Status: run AutoSSL for the domain so the site loads over https://.
  2. Email → Email Accounts: create e.g. noreply@example.com. You'll enter its SMTP details in the Superadmin panel (System settings → Email).
  3. In File Manager edit invoiceapp/.env (enable Show Hidden Files in Settings) and confirm: 
    APP_ENV=production
APP_DEBUG=false
APP_URL=https://billing.example.com
SESSION_SECURE_COOKIE=true
  4. If your host doesn't offer Redis, switch to the shared-hosting drivers in the same file (see Redis): 
    CACHE_DRIVER=file
SESSION_DRIVER=file
QUEUE_CONNECTION=sync
INERTIA_SSR_ENABLED=false
ℹ️ Note

After editing .env on a live site, clear the config cache: run php artisan config:clear in cPanel Terminal, or wait for the next deploy. If you never ran config:cache, changes apply immediately.

Installing on Plesk #

  1. Websites & Domains → (your domain) → PHP: choose PHP 8.3 or 8.4 (FPM served by Apache or Nginx), and raise memory_limit and max_execution_time.
  2. Databases → Add Database: create the database and a user, and note the credentials.
  3. Files: upload the zip to the domain folder (e.g. /httpdocs/../invoiceapp or /invoiceapp) and extract it.
  4. Hosting & DNS → Hosting Settings: set Document root to invoiceapp/public.
  5. If you use Nginx-only hosting, add this under Apache & nginx Settings → Additional nginx directives: 
    location / { try_files $uri $uri/ /index.php?$query_string; }
  6. Open the site and complete the web installer.
  7. Scheduled Tasks → Add Task: type Run a PHP script, script invoiceapp/artisan, arguments schedule:run, PHP 8.3/8.4, run Cron style * * * * *.
  8. SSL/TLS Certificates: install a free Let's Encrypt certificate and enable Redirect from HTTP to HTTPS.

The Plesk Laravel Toolkit extension also works. Point it at invoiceapp and it handles the document root, Artisan and the scheduler for you.

Installing on DirectAdmin #

  1. Extra Features → PHP version selector (or Domain Setup → PHP version): choose 8.3 or 8.4.
  2. Account Manager → MySQL Management → Create new database.
  3. Upload and extract the zip into /home/USER/domains/example.com/invoiceapp.
  4. Make public_html point to the app's public folder (from SSH): 
    cd ~/domains/example.com
mv public_html public_html.bak
ln -s invoiceapp/public public_html
  5. Run the web installer, then add a cron job under Advanced Features → Cron Jobs: 
    * * * * * /usr/local/bin/php /home/USER/domains/example.com/invoiceapp/artisan schedule:run >/dev/null 2>&1
  6. Enable a Let's Encrypt certificate under SSL Certificates.

VPS / command-line install #

This applies to Ubuntu 22.04/24.04 with Nginx, PHP-FPM 8.4, MySQL and Redis. The commands are a guide; adapt them to your distro.

sudo apt install nginx mysql-server redis-server supervisor \
  php8.4-fpm php8.4-cli php8.4-mysql php8.4-mbstring php8.4-xml php8.4-bcmath \
  php8.4-curl php8.4-zip php8.4-gd php8.4-intl
cd /var/www && sudo unzip invoiceapp.zip -d invoiceapp
sudo chown -R www-data:www-data invoiceapp/storage invoiceapp/bootstrap/cache

Nginx server block:

server {
    listen 80;
    server_name billing.example.com;
    root /var/www/invoiceapp/public;
    index index.php;
    client_max_body_size 12M;

    location / { try_files $uri $uri/ /index.php?$query_string; }
    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
    }
    location ~ /\.(?!well-known) { deny all; }
}

Then open the site to run the web installer, or install from the CLI instead:

cp .env.example .env            # then edit DB_*, APP_URL, APP_ENV=production, APP_DEBUG=false
php artisan key:generate
php artisan migrate --seed --force
php artisan storage:link
php artisan optimize
echo '{"installed_at":"'$(date -Iseconds)'"}' > storage/installed   # disables the installer

Add the scheduler to the web user's crontab (sudo crontab -u www-data -e):

* * * * * php /var/www/invoiceapp/artisan schedule:run >> /dev/null 2>&1

Finish with HTTPS (sudo certbot --nginx), Horizon and optionally SSR.

Redis, queues & Horizon #

Choose the setup that matches your hosting:

Shared hosting (no Redis)VPS (recommended)
.envCACHE_DRIVER=file
SESSION_DRIVER=file
QUEUE_CONNECTION=sync		CACHE_DRIVER=redis
SESSION_DRIVER=redis
QUEUE_CONNECTION=redis
EmailsSent during the request (a slightly slower click on "Send")Queued and sent in the background with automatic retries
WorkerNone neededLaravel Horizon under Supervisor

The Supervisor program for Horizon (/etc/supervisor/conf.d/invoice-horizon.conf):

[program:invoice-horizon]
command=php /var/www/invoiceapp/artisan horizon
user=www-data
autostart=true
autorestart=true
redirect_stderr=true
stdout_logfile=/var/www/invoiceapp/storage/logs/horizon.log
stopwaitsecs=3600
sudo supervisorctl reread && sudo supervisorctl update && sudo supervisorctl start invoice-horizon
  • Horizon processes three queues: high, default and mail, each with 3 attempts.
  • The dashboard is at /horizon (also Superadmin → Queues (Horizon)). It is visible only to a signed-in Superadmin.
  • Horizon needs the pcntl and posix extensions, so it runs on Linux only. If your host doesn't allow it, run php artisan queue:work redis --queue=high,default,mail --tries=3 --max-time=3600 under Supervisor instead.

Server-side rendering (SSR) #

With SSR, the server sends fully rendered HTML. The first paint is faster and search engines see the content of your marketing pages and blog. SSR is optional: without it, pages render in the browser and everything still works.

  • Shared hosting: set INERTIA_SSR_ENABLED=false. Shared plans rarely allow a permanent Node.js process.
  • VPS: install Node.js and keep the SSR server running with Supervisor:
[program:invoice-ssr]
command=php /var/www/invoiceapp/artisan inertia:start-ssr
user=www-data
autostart=true
autorestart=true
redirect_stderr=true
stdout_logfile=/var/www/invoiceapp/storage/logs/ssr.log

It listens on 127.0.0.1:13714. After every front-end rebuild run php artisan inertia:stop-ssr; Supervisor then restarts it with the new bundle.

Superadmin: first login #

The Superadmin login is at https://your-domain/superadmin/login.

  1. Sign in with the Superadmin email and password you entered in the web installer. If you installed from the command line, sign in with the default admin@invoiceapp.com / password and do the next step before anything else.
  2. Click your avatar (top right) and choose Your account. There you can change your name and email (a new email needs your current password) and your password (needs the current password; at least 8 characters with upper and lowercase letters and a number). Changing the password signs out your other devices.
  3. Work through System settings in this order: General, then Email, then Stripe, then Payouts.

Recovery: reset the login from the command line #

If you are locked out (forgotten password, or an email address you can no longer use), set a new email and password with tinker. Use cPanel Advanced → Terminal or SSH, and replace CURRENT-EMAIL with the Superadmin's current email:

cd ~/invoiceapp
php artisan tinker --execute="echo App\Models\Superadmin::where('email','CURRENT-EMAIL')->update(['email'=>'you@your-domain.com','password'=>bcrypt('YOUR-LONG-UNIQUE-PASSWORD')]);"

It prints 1 when one account was updated. If you don't know the current email, list the accounts with php artisan tinker --execute="echo App\Models\Superadmin::pluck('email');". Without Terminal or SSH, add the command as a one-off cPanel cron job: prefix it with cd /home/myuser/invoiceapp && and use the full PHP path. Let it run once, then delete the cron job so the password doesn't stay in the cron list.

The Superadmin sidebar has four groups: Overview (Dashboard), Business (Tenants, Plans, Payouts, Reports), Content (Pages, Blog posts, Menus, Landing page) and System (General, Stripe, Email, Payout settings, Updates, Queues).

Superadmin: system settings #

General

Site name and tagline, logo and favicon (with an option to hide the name next to the logo), support and contact emails, footer text, and SEO description, keywords and share image. Here you can also:

  • Turn email verification for new sign-ups on or off. On is recommended because it blocks fake accounts.
  • Paste a Google Analytics or other tracking snippet and a live-chat widget script. They are added to the public website.

Email (SMTP)

Enter your mail server details: host, port (465 SSL or 587 TLS), username, password, encryption and the From name and address. On cPanel use the email account you created and the host mail.your-domain.com. Saved passwords are never shown again; leave the field blank to keep the current one.

💡 Tip

Test it by using Forgot password on a tenant account, or by emailing an invoice to yourself. Without working email, sign-up verification and invoice emails won't arrive.

Stripe (platform account)

  1. In your Stripe Dashboard → Developers → API keys copy the publishable (pk_…) and secret (sk_…) keys for test and live mode.
  2. Paste them, enable Stripe, and choose Test mode while you try things out.
  3. In Stripe → Developers → Webhooks → Add endpoint, use the webhook URL shown on the settings page (https://your-domain/stripe/webhook) and select the event payment_intent.succeeded. Copy the signing secret (whsec_…) back into the settings.
  4. When you're ready, switch to Live mode.

The platform account collects subscription payments from tenants. It also collects invoice payments for every tenant that chooses platform payments; you later pay those tenants through Payouts.

Payout settings

Set the platform fee percentage deducted from each payout and the minimum payout amount a tenant must have before requesting one.

Superadmin: plans & subscriptions #

Business → Plans. Three plans are seeded: Free Tier, Pro and Enterprise. For each plan you can set:

  • Name, slug, description, price and billing cycle (monthly / yearly).
  • Limits: max invoices, clients, users, products. Leave a limit empty for unlimited.
  • Plan options: online payments (Stripe), custom branding and API access.
  • A feature list and display order for the public /pricing page, Popular (highlights the plan) and Active.

A plan that still has subscribed companies can't be deleted. Move those companies to another plan first, or deactivate the plan instead. Tenants upgrade themselves under Settings → Subscription and pay by card through the platform Stripe account.

Superadmin: managing tenants #

Business → Tenants lists every company and its owner. Search, then open a tenant to see its usage, plan and status. From Edit you can:

  • Update the user's name, email, phone and role, or deactivate the account so it can no longer sign in.
  • Change the company's plan and subscription status (active, trial, cancelled, expired). This is useful for support, comps or manual billing.
  • Delete the user.

The Dashboard shows companies, MRR, paying customers, trials, the last 30 days of payment volume, pending payouts, and 12-month signup and volume charts.

Superadmin: payouts #

When a tenant's clients pay through the platform Stripe account, that money is in your Stripe balance. Tenants request it back from their Payouts page.

  1. Business → Payouts lists requests by status (pending / completed / rejected).
  2. Open a request to see the gross amount, the platform fee, the net amount to send, the included payments and the tenant's bank or PayPal details (each has a copy button).
  3. Send the money from your bank or PayPal, then click Mark as completed and enter the transaction ID and optional notes.
  4. Or click Reject with a reason. The payments are released so the tenant can request them again.

Superadmin: website, pages, blog & menus #

  • Landing page: hero texts, trust badges, feature cards and testimonials. Each list can be added to, removed from and reordered, and icons show a preview.
  • Pages: create CMS pages at /page/{slug} (privacy, terms, about…). There are two editing modes: Classic (a rich-text editor with an HTML source view) and Blocks. Blocks is a page builder with hero, features, columns, image, call-to-action, FAQ and more. Toggle "Show title" and "Full width" as needed.
  • Blog posts: title, slug, excerpt, featured image, rich-text content and publish status. Published posts appear at /blog.
  • Menus: links for the header and footer locations. A link can be a site path (/pricing), an anchor (#features) or a full https:// URL.

Superadmin: reports #

Business → Reports shows MRR, ARR, payment volume and platform fees for a chosen date range, plus monthly trends, active subscriptions per plan and the top companies by volume.

Superadmin: updates & backups #

System → Updates checks the configured update server for a new version. Download & install first backs up files and the database, then applies the update. Downloads are only accepted from the configured update-server host. Before any update, also take your own backup (cPanel Backup or JetBackup).

Tenants: sign up & onboarding #

  1. A business owner clicks Get started on the website, or goes to /register, and enters their name, company, email and password.
  2. They confirm their email through the verification link. Sign-ups are protected by rate limits, a spam honeypot and a disposable-email block.
  3. The onboarding wizard collects company details, logo, currency and invoice preferences. It can be skipped and finished later in Settings.
  4. They land on the Dashboard: revenue, outstanding and overdue totals, recent invoices and quick actions.

Tenants: company settings #

Settings is available to Owners and Admins and has these tabs:

TabWhat you set

InvoicesNumbering prefix and start number, default due days, tax, PDF template (12 designs, with live preview).
QuotationsNumbering, validity period, template.
PaymentsAccept card payments; choose platform payments (no Stripe account needed, paid out via Payouts) or your own Stripe account (paste your keys and webhook secret; the money goes straight to you).

Notes & termsDefault notes and terms printed on every invoice and quotation.

Settings → Subscription shows the current plan and its usage, and lets you upgrade with a card.

Tenants: clients & products #

  • Clients: name, company, email, phone, billing address and tax number. A client's page shows all their invoices, quotations and payments. You can also add a client on the fly from the invoice editor ("Quick add").
  • Products: products and services with a price, unit and tax rate. Pick them while writing invoices to fill line items instantly.

Tenants: quotations #

  1. Quotations → New: choose the client, add line items (from products or free text), discount, tax, notes and an expiry date.
  2. Send emails the client a secure link. Download gives you the PDF.
  3. The client accepts or rejects online, and can pay immediately if card payments are on. You can also mark it accepted or rejected yourself.
  4. Convert to invoice creates an invoice from an accepted quotation with one click.

Expired quotations are marked automatically each day.

Tenants: invoices #

  1. Invoices → New: client, issue and due dates, line items, discount, tax, notes and terms. The totals and the preview update live.
  2. Save as draft, then Send (emails the client a secure link with a PDF) or copy the public link yourself.
  3. Track the status: draft → sent → partially paid → paid, or overdue (set automatically after the due date).
  4. Record payments: the client pays online by card, or you click Record payment for cash or bank transfers (partial payments are allowed). Mark as paid settles the full balance.
  5. Other actions: Duplicate, Download PDF, Preview, Delete, and Export (CSV) from the list page.

Tenants: recurring invoices #

Use these for retainers and subscriptions. Create a template with a name, the client, line items, discount, notes and terms. Then set the billing cycle (weekly, monthly, quarterly, every 6 months or yearly), the start date, and optionally an end date or a limit on how many cycles to bill. Tick Auto-send to email each generated invoice to the client automatically.

  • The daily scheduler generates due invoices. This needs the cron job.
  • Pause, Resume, Cancel or Generate now at any time.

Tenants: payments & receipts #

  • Payments lists every payment (card or manual) with its method, date and invoice. Open one to see details or issue a refund.
  • Receipts are created for payments. Preview them, or download them as PDF to send to clients.

Tenants: requesting payouts #

This applies only when you use platform payments. The Payouts page shows your available balance (card payments not yet paid out, minus refunds), the amount pending and the total paid out.

  1. Click Request payout. The whole available balance is requested at once, and it must be at least the platform's minimum.
  2. Choose bank transfer (bank name, account name, account number or IBAN, and optionally routing/SWIFT) or PayPal (PayPal email). Your bank details are pre-filled from earlier requests.
  3. The platform fee is deducted and you'll see the net amount. The request then shows completed (with the transaction ID) or rejected (with a reason; the payments become available again).

Tenants: expenses & reports #

  • Expenses: record business costs with a title, category, amount, tax, date, vendor and reference. You can mark an expense as billable to a client and attach a photo or PDF of the receipt (up to 5 MB). The list filters by category and date and shows the totals.
  • Reports: revenue and other key figures with charts. Pick a period such as this or last month, quarter or year, or set a custom range.

What your client sees #

A client opens the link from the email (/invoice/{token} or /quotation/{token}). The link is long and unguessable, and no account is needed. On that page the client can:

  • View the branded document and download the PDF.
  • Pay by card through Stripe. The invoice updates to paid instantly, and a receipt is recorded.
  • For quotations: accept, reject, or accept and pay.

Maintenance & upgrading #

Back up the database and the storage/app folder (uploaded logos, receipts, media) regularly.

To upgrade manually with a new release package:

  1. Back up the files and the database.
  2. Upload the new files over the old ones. Keep your .env and storage/, and don't upload install.json again.
  3. Run the following via SSH or cPanel Terminal: 
    php artisan down
php artisan migrate --force
php artisan optimize:clear && php artisan optimize
php artisan horizon:terminate      # only if you use Horizon
php artisan inertia:stop-ssr       # only if you use SSR
php artisan up

Without SSH, you can create a temporary cPanel cron job that runs php …/artisan migrate --force once, then delete it.

Security checklist #

  • ☐ The Superadmin signs in with its own email and a strong, unique password, set in the web installer or under Your account. Command-line installs: the default admin@invoiceapp.com / password login no longer works.
  • ☐ APP_ENV=production and APP_DEBUG=false.
  • ☐ The document root is public/; https://your-domain/.env returns 403/404.
  • ☐ HTTPS is enforced, and SESSION_SECURE_COOKIE=true.
  • ☐ Stripe webhook secrets are set; live keys are used only after testing in test mode.
  • ☐ Daily backups of the database and storage/app are in place.
  • ☐ install.json is no longer in the root, or storage/installed exists. Both disable the installer.
  • ☐ PHP and the server are kept up to date.
